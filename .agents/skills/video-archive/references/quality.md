# 从目标到小样方案

推荐应引用本次扫描的具体事实，例如“多数容量来自 4K60、10-bit BT.709”，不要只列编码器名称。

| 用户目标 | 可以提出的候选方向 | 需要解释的取舍 |
|---|---|---|
| 家庭观看、减少副本体积 | 设备支持 HEVC 时，libx265、medium，CRF18/20/22 作为起始比较组 | 这是候选范围，不是质量保证；实际体积由内容决定 |
| 尽量保留细节、后续轻量剪辑 | 可向较低 CRF 测试，例如 16/18/20，并保留原片 | 有损重编码仍损失信息，长 GOP 副本不是剪辑母版 |
| 更广泛的旧设备兼容 | 8-bit 素材可比较 libx264、medium，例如 CRF18/20/22 | 需要在目标设备实测；不同编码器的同一 CRF 不代表相同画质 |
| 时间更重要 | 对所选编码器比较 faster/fast 与 medium | preset 改变编码取舍，需要新小样；不保证速度或体积比例 |
| 上传平台有严格体积上限 | 先问时长、字节限制、容器/音频要求 | CRF 不能保证目标体积；首版不自动执行码率预算或两遍编码 |
| 专业剪辑、HDR/Log 调色、长期母版 | 先明确后续处理链，保留原素材 | 首版无调色/HDR转换/中间格式功能，不硬套观看副本方案 |

以上数值是测试起点。不要以历史某批小样的节省率承诺新用户结果，也不要称有损压缩为无损。

脚本支持 H.264/HEVC 输入的 yuv420p/yuv420p10le、完整 BT.709 标签；libx264 输出仅接受 8-bit，10-bit 保持原色深并使用 libx265。不改帧率、分辨率、显示方向或已知色彩标签。BT.709 标签不是拍摄模式证明，拍摄模式不明时向用户求证；疑似 Log 单独处理。

每个选定 Profile 至少选一个代表片段，类型多时分批。优先覆盖高运动、细密纹理、低照度、渐变；没有画面证据时不能声称已覆盖这些场景。常规每段 15–60 秒，短视频可整段使用；开始位置和时长由 AI 写入计划并向用户说明。每组候选读取同一 reference。遇到复杂 GOP 无法制作可比片段时换片段或缩小范围，不降低校验标准。

观看时在同一播放器、相同尺寸、同一时刻对比，再在常用设备播放。记录用户选择的参数、画质评价与适用范围。样品编码时间可用于粗略估算，同 Profile 的时长比例只是近似；长片、噪点和运动复杂度都会改变结果。

编码参考：[FFmpeg libx264/libx265 文档](https://ffmpeg.org/ffmpeg-codecs.html)、[x265 质量与 CRF](https://x265.readthedocs.io/en/stable/cli.html#quality-rate-control-and-rate-distortion-options)。新增算法或硬件编码参数前核对对应官方文档。
